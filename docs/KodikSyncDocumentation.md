# Документация по Kodik Sync

## Обзор системы

Kodik Sync - это система синхронизации данных между сервисом Kodik и Shikimori. Она обеспечивает автоматическую загрузку информации о аниме, эпизодах и переводах из базы Kodik в локальную базу данных приложения.

## Архитектура системы

### Основные компоненты:

1. **База данных (PostgreSQL)**
   - Использует Prisma ORM для работы с данными
   - Хранит информацию о материалах, эпизодах и переводах
   - Структура моделирована через schema.prisma

2. **API сервера**
   - Предоставляет REST API для взаимодействия с системой
   - Обрабатывает запросы по загрузке обложек и информации о материалах
   - Управляет пользователями и сессиями

3. **Система синхронизации**
   - Автоматическая проверка обновлений через定时 (встроенный планировщик)
   - Обработка запусков sync вручную или автоматически

### Структура базы данных:

**Модели данных:**

1. `KodikSyncSettings` - настройки синхронизации
2. `CoverCacheSettings` - настройки кэширования обложек  
3. `KodikSyncRun` - история запусков sync
4. `KodikImportJob` - состояние полного импорта
5. `KodikMaterial` - информация о материалах Kodik
6. `KodikSeason` - сезоны аниме
7. `KodikEpisode` - эпизоды аниме
8. `KodikEpisodeRelease` - новые серии (лента)
9. `User` - пользователи системы
10. `UserListSync` - метаданные синхронизации списков
11. `UserAnimeListEntry` - записи списка аниме пользователя
12. `UserAnimeBookmark` - закладки аниме
13. `ShikimoriAccount` - OAuth токены Shikimori
14. `Session` - серверные сессии
15. `UserWatchProgress` - прогресс просмотра
16. `AdminTodo` - задачи для администратора
17. `OAuthState` - OAuth state

## Основные функциональные возможности:

### 1. Автоматическая синхронизация
- Cron запускает `npm run kodik:sync:scheduled` каждую минуту; сам скрипт читает `KodikSyncSettings`
  и запускает Kodik sync только когда прошёл `intervalMinutes`
- Настройка интервала проверки обновлений и количества страниц (`syncPages`)
- Поддержка ручного запуска синхронизации
- Логирование истории запусков и ошибок
- Scheduled-скрипт также запускает Shikimori anons sync и worker отложенных уведомлений

### 2. Кэширование обложек
- Управление параметрами кэширования (качество, максимальная высота)
- Настройка времени жизни кэша

### 3. Импорт данных
- Поддержка полной имитации с состоянием продолжения после остановки
- Обработка ошибок и восстановление при неудачах

### 4. Работа с пользователями
- OAuth через Shikimori для аутентификации пользователей
- Система сессий и токенов
- Управление списками аниме пользователей (добавление в избранное, записи списка)

### 5. Прогресс просмотра
- Хранение позиций просмотра эпизодов для каждого пользователя

## Технические детали:

### API Endpoints:
1. `/api/cover` - загрузка обложек материалов
2. `/api/sync` - запуск синхронизации данных
3. `/api/import` - управление импортом
4. `/api/user` - работа с пользовательскими данными

### Требования:
- Node.js 18+ (предположительно)
- PostgreSQL 13+
- Prisma ORM

## Использование:`r`n

Синхронизация запускается сервером по расписанию или вручную через административный интерфейс. История запусков и ошибки сохраняются в базе данных.

## CLI/cron ограничения

`scripts/kodik-sync-scheduled.ts` выполняется обычным Node/tsx процессом, не через Next.js runtime.
Модули, которые попадают в его граф импортов, не должны содержать `import "server-only"`: пакет
`server-only` предназначен для Next-бандлера и при прямом Node-импорте бросает ошибку. Это особенно
важно для notification channel модулей, которые используются во время сохранения новых релизов.

Эта система позволяет автоматически поддерживать актуальную информацию о аниме и пользователях, обеспечивая бесперебойное взаимодействие с сервисами Kodik и Shikimori.
